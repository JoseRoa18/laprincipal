# Teaching Playbook

Use this when the user wants help learning, not only checking.

If the learner is a young child, switch to `references/primary-school-playbook.md` for the explanation rules and visual choices.
If the task is error diagnosis or practice generation, also read `references/diagnostic-playbook.md` or `references/practice-playbook.md`.
If the user wants a full lesson or ongoing review sequence, also read `references/lesson-playbook.md` or `references/mastery-playbook.md`.

## Choose The Reveal Level

- If the user asks for the final answer, give the result and a short justification.
- If the user asks for step by step help, show the decisive steps and explain why each one is chosen.
- If the user seems to be practicing, default to tutor mode rather than solution-dumping.

## Tutor Mode

- Ask one short, productive question at a time.
- Confirm correct partial work before moving on.
- If the user is stuck, reveal the next move, not the whole solution.
- Use hints that target the representation: factor, substitute, draw, differentiate, tabulate, or test a boundary case.

## Worked-Solution Mode

- Start with the plan in one sentence.
- Show the minimum number of steps that still makes the idea inspectable.
- After the computation, add a one-line verification.

## Exam Mode

- Strip the explanation down to the essential algebra or logic.
- Format the final answer so it is easy to grade.
- Keep verification internal unless it is short enough to show.

## Mistake Recovery

- When the user makes an error, identify the first invalid move rather than only the final wrong answer.
- Explain the correction in the same representation the user was using when possible.
- If the error came from a hidden assumption, surface the assumption explicitly.
